# RC15 平台修复设计

已确认保留 Electron 44.0.0，macOS 最低版本为 13.0。Shell 从 RC15 发布分支创建 `codex/rc15-platform-repair-20260921`；Core 从已发布 Runtime 提交 `fbbcc26c251a800929cd5414a23940974ad3453b` 创建独立修复分支。

## 系统兼容与升级

应用声明 macOS 13.0，更新元数据声明 Darwin 22.0.0。合并架构元数据时拒绝不一致或缺少的系统要求。现有 v1 签名清单采用严格字段校验，不能直接添加字段；系统要求保留在现有的 updater-metadata 文件中，其摘要已经纳入签名清单。新版发现更新时先验证该文件摘要，再判断系统支持情况。旧版仍能解析 v1 清单并由 electron-updater 拦截不兼容系统。

## 本地状态修复

托管 Profile 升级至第 8 代，按插件包身份移除已退役 GenUI/Market 的依赖、bundle 和本地包，失效安装标记及锁文件。迁移必须可重复执行，中断后下一次启动继续。无需全量删除用户数据。安装目录清理由现有 NSIS 兼容卸载器负责，复核其失败路径，不能绕过失败直接覆盖旧 Runtime。

登录离线页增加本地重置入口，清除凭据和独立认证 Session 的缓存/连接/存储后回到登录。所有在途恢复结果必须受会话代次约束，防止重置后重新写回旧登录。网络日志只记录 origin、固定 endpoint、错误名称/标准错误码和状态码，不记录令牌、请求内容或完整异常文本。网络故障本身不能被宣称通过清理数据修复。

## Windows 控制台

现有 windowsHide/SW_HIDE 只能约束初始可见性，不能证明没有任务栏窗口。先检查普通和受限令牌的创建路径。禁止直接将 CREATE_NO_WINDOW 应用于受限目标：现有记录表明会导致 0xC0000142。实现必须保留 Job、取消、管道输出和沙箱策略，并提供 Windows 原生验证。macOS 单元测试不能替代 Windows 桌面视觉验收。

## 发布门槛

通过 Shell 类型检查、升级与迁移专项测试、Core 相关测试；Windows 10/11 三种权限模式分别连续 20 次命令，无任务栏闪烁、无 0xC0000142，取消和输出正常；Mac 两种架构完成升级与登录验证。此次工作不自动发布资产或移动生产指针。
