# 登录基线文档资产整理设计

## 目标

从知识库提交 `71cdeb5` 之后开始，整理 2026-08-27 至 2026-08-28 已发生但尚未完整沉淀的客户端研发事实。本轮只记录已经实现、自动验证或经用户手工确认的内容，并为下一阶段业务开发提供明确入口。

## 双层文档职责

Shell 仓库是客户端工程事实的权威来源。它保存登录与会话实现、账号数据隔离、Harness 单侧栏集成、第一方桌面插件、设置入口、品牌资产、开发和构建约束、提交映射、验证证据、已知限制及后续维护步骤。后续维护者应能只依赖 Shell 文档完成问题定位和升级判断。

BoxserObsidian-Canvas 知识库用于跨产品与研发协作。它只提炼必要的实施过程、用户可见结果、前端职责、跨角色依赖、阶段状态和未决问题；不复制 Shell 的命令、文件清单、故障时间线或内部实现细节。知识库通过 `SRC_INSAI_DESKTOP_SHELL` 引用工程证据。

## Shell 资产结构

新增一份阶段基线与交接文档，集中记录：

- 从 rc.9 稳定宿主进入登录切片后的提交和能力范围；
- Main、Renderer、Harness View、账号 Profile 和第一方集成插件的当前职责；
- 验证码/密码登录、会话恢复、退出和多账号隔离的实现结果；
- 单侧栏、账号菜单、统一设置入口和 Better Sidebar 的组合方式；
- 因赛AI品牌源、系统图标及上游视觉隔离规则；
- 自动测试、开发模式人工验收和仍待安装包验证的证据；
- upstream、Core Runtime、第一方插件及品牌修改的升级顺序；
- 进入下一业务阶段前必须保持的回归门禁和已知后续项。

现有 `architecture.md` 保持为架构入口，链接阶段交接文档和已批准的专题设计。`client-build-runbook.md` 只保存可复用的构建与验证规则；单次实施过程不重复写入 Runbook。`development.md` 与本地组合开发文档只在内容已经可执行且与当前仓库一致时一并提交。构建产物、用户数据、临时日志和下载制品不进入版本控制。

## 知识库资产结构

新增 `INSIGHT-FE-003` 前端实施记录，覆盖登录、单侧栏、设置和品牌统一这一完整垂直切片。同步更新：

- 业务阶段路线图中的完成状态和下一阶段入口；
- 登录、会话与业务数据隔离前端接入需求中的已实现证据和仍待后端确认项；
- 前端研发索引、知识库总索引、执行日志和对话事实摘要；
- `open-questions` 中已由本轮实现收敛的部分，以及仍属于产品或后端的决策。

知识库不会把前端实现自动升级为后端正式契约。页面可记录“前端已实现并手工验收”，但跨端契约在 Product 与 Backend 确认前继续保持 `draft`。

## 证据与完成标准

本轮以 Shell Git 提交、已有自动检查结果和用户手工验收为证据。文档必须明确区分 `passed`、`passed-by-user`、`not-yet-verified`，不得把开发模式验收写成 macOS/Windows 安装包验收。

完成时应满足：

1. Shell 文档能独立解释当前客户端结构、已交付能力、验证结果和下一次升级方式。
2. 知识库能说明阶段成果、产品影响和跨角色待办，而不镜像 Shell 细节。
3. 两个仓库的索引和内部链接有效，文档不包含新增个人绝对路径或构建产物。
4. 两个仓库分别提交，现有无关工作区修改不被带入。
