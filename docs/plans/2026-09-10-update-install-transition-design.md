# 客户端更新安装过渡设计

日期：2026-09-10

## 目标

在不改变 OSS、签名 Manifest、electron-updater、安装包格式和平台安装顺序的前提下，消除点击“安装并重启”后出现的长时间空白窗口，并确保安装准备阶段发生的错误能够被用户看见和恢复。

## 根因

客户端进入 `installing` 状态后会先停止工作区，然后主动关闭更新窗口，最后才调用平台更新器。停止工作区会移除承载实际客户端界面的 `WebContentsView`，主窗口底层只剩空的认证宿主；更新窗口又被提前关闭，因此 macOS Squirrel 在本地读取、解包和准备签名应用期间，用户只能看到空白主窗口。

macOS 更新使用 blockmap 减少网络传输，但最终仍需在本机验证、解包并原子替换完整签名 `.app`。这不是可在 1.0 阶段安全改造成热更新的流程。

## 方案选择

### 采用：保留更新窗口直到平台更新器关闭应用

- 继续先停止工作区和内置运行时，避免 Windows NSIS 或 macOS 安装期间发生文件占用。
- 安装准备阶段不再主动关闭更新窗口；关于、插件恢复和安全模式等无关辅助窗口仍按原顺序关闭。
- 更新窗口显示准确的安装准备文案、持续的不确定进度条和一次性 Logo 状态确认动效，不展示无法验证的百分比。
- electron-updater 真正准备好安装后，由平台更新器正常关闭窗口并退出应用。
- 安装阶段收到异步更新器错误时，将状态切换为现有 `error` 状态，保留重试和完整安装包兜底入口。

这是改动最小且跨平台风险最低的方案。它消除应用仍在运行时的空白窗口，同时不介入平台安装器内部生命周期。

### 不采用：主窗口全屏安装遮罩

该方案需要给认证宿主增加新的安装状态 IPC，并确保工作区视图关闭后遮罩仍然可靠显示。它能覆盖用户主动关闭更新窗口的边缘情况，但改动跨越主窗口启动状态机，1.0 阶段收益不足以抵消回归风险。

### 不采用：独立安装助手或远程热更新

独立助手才能在应用退出后继续展示界面，但需要新增签名进程、生命周期、失败恢复和平台差异处理。远程替换渲染代码还会新增远程代码执行、签名、回滚和版本兼容边界。两者都不进入 1.0。

## 状态与交互

1. 用户点击“安装并重启”。
2. `UpdateManager` 发布 `installing` 状态。
3. 更新窗口立即显示：
   - 标题：`正在准备安装…`
   - 说明：`正在安全关闭当前工作区并准备安装文件。完成后因赛AI 将自动退出并重新打开。`
   - 持续的不确定进度条和一次性 Logo 状态确认动效。
4. 主进程等待工作区和运行时停止，但保持更新窗口可见。
5. 平台更新器完成本地准备后关闭应用、替换客户端并重新启动。
6. 如果第 4 或第 5 步发生错误，更新窗口切换为错误状态，不允许错误被静默丢弃。

动效只用于确认状态已切换并表达仍在工作，不映射虚假进度。Logo 只做 400ms 的进入确认，长时间反馈由不确定进度条承担。系统启用 `prefers-reduced-motion: reduce` 时禁用 Logo 动画，进度状态仍通过文字表达。

## 安全与兼容边界

- 不改变 `autoInstallOnAppQuit: false`，避免普通退出意外安装更新。
- 不延后工作区停止动作，确保 Windows 安装器仍在运行时资源释放后启动。
- 不改变下载、blockmap、SHA-512 校验、Manifest 验签、渠道选择或完整安装包兜底。
- 不添加新依赖，不修改应用身份、用户数据目录或钥匙串策略。
- 平台更新器接管退出后，应用进程无法继续展示过渡 UI；1.0 不增加外部助手进程。

## 错误处理

- `prepareToInstall()` 同步或异步失败：沿用现有 `install()` 捕获逻辑，显示错误且不调用平台安装器。
- 下载期间更新器错误：继续拒绝当前下载完成 Promise，由下载流程统一进入错误状态。
- `installing` 期间平台更新器异步报错：直接发布带当前版本上下文的错误状态。
- 其他无活动下载、非安装状态下出现的孤立更新器错误不改变 UI，避免陈旧事件覆盖稳定状态。

## 验收

- 点击“安装并重启”后，更新窗口持续可见，主窗口不再单独暴露为空白窗口。
- 安装准备阶段显示准确文案和连续的不确定进度动效，无虚假百分比。
- macOS 和 Windows 均保持“先停止工作区，再启动安装器”的顺序。
- 平台更新器异步失败时显示可恢复错误，不会无限停留在安装准备状态。
- 平台安装开始后应用正常退出并重新拉起，版本升级成功，登录信息和用户数据保持不变。
- 更新窗口、更新状态机、安装顺序相关测试以及 TypeScript 检查和构建全部通过。
