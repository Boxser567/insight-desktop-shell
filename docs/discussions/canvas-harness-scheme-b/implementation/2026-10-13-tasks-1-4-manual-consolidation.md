## 一、当前到底能做什么

### 通过Harness Agent对话可用的五个工具

| 能力 | 工具 | 实际范围与限制 |
| --- | --- | --- |
| 创建空画布 | `canvas_create` | 可指定名称；返回真实画布ID；准备插件服务，不自动打开画布；不生成素材 |
| 读取画布与节点 | `canvas_get` | 默认summary是摘要；`view:nodes`返回节点详情与版本；`refresh:true`从后端权威重载；可指定节点ID |
| 新增普通节点 | `canvas_node_edit` | **仅action:add**；text/image/video/audio。支持标题、位置、提示词；正文仅text。图片/视频可填写原生允许的技术参数，但不开放模型/模式切换；不生成 |
| 发现聊天图片 | `canvas_assets` | 当前模型可见用户消息中的图片引用；按最近出现去重排序，最多展示20条，同时报告总数及截断；不上传、不写画布 |
| 导入图片素材 | `canvas_asset_import` | 当前聊天图片，或有访问权限的已有画布image节点产物；新建image/upload来源节点；保存后单独报告资产登记结果；不生成 |

普通媒体节点与图片素材节点不同：前者可以保存提示词及原生默认生成配置，本轮不执行模型；后者保存已有图片URL并显示该图片，`contentType:upload`、`generation:null`。图片素材导入不要求配置生成模型。

普通image/video/audio新增依赖当前账号的原生默认模型、模式与权限。若没有有效默认配置，正确结果是明确的 `CONFIGURATION_ERROR` 且不新增，不应伪造成功。这与图片素材导入失败不是同一个问题。

### 已完成的服务底座

- **执行位置**：Host负责工具路由、创建API和素材解析/上传/登记；Client中的插件服务复用原生Store、节点方法与持久化队列处理读写。无需先挂载可见画布iframe。
- **无界面上下文**：按画布ID初始化服务；打开原生画布时复用同一业务上下文；关闭画布面板仍可在运行且已连接的Shell/Harness内操作。这里不承诺退出Shell或停止Harness后继续接受Agent命令。
- **通信**：Host/Client使用既有本地HTTP/SSE桥传命令、上下文状态和回执，不依赖Agent反复查询。原画布已有的生成结果监听保持原有方式；本轮未新增完整媒体任务聊天反馈。
- **严格保存与版本检查**：saved来自原持久化队列回执，不把accepted/started当作保存成功；队列内检查expectedVersion，冲突不强写。
- **编辑保护**：活动编辑、草稿和在途写入参与guard及可信读取判断；Agent不能通过权威刷新覆盖未提交编辑。
- **去重与未知结果**：同一真实工具调用重复运输只执行一次；写入结果未知时不自动重发。去重限定当前运行生命周期，不承诺重启后全局exactly-once。
- **素材边界**：聊天图片引用来自真实当前会话；模型不能传任意路径、凭证或URL；账号/环境变化会再次检查。图片支持PNG/JPEG/WEBP/GIF且小于20MiB，但Harness可能已缩放或调整朝向，不承诺原文件字节保真。

### 暂未开放给Agent的行为

原生adapter内部已有普通节点update/delete/run适配；**当前桥与模型工具只开放read、node.add、asset.add**。因此不能通过现有对话工具修改/删除已存在节点、增删连线、执行生成、导入执行模板或调用完整场景Skill。用户在原生UI手动使用这些成熟业务能力不受此范围影响。

普通文件附件的原始图片、视频/音频文件导入、压缩后不再对模型可见的历史图片也不在当前素材范围。已有画布图片可通过明确canvasId/nodeId复用；不能凭“上个会话那张图”扫描其他会话附件。

## 二、怎样判断一次手测通过

每项至少核对三层证据：

1. **轨迹中的真实画布工具入参/结果**：不是只看Agent最后一句“成功”。
2. **从后端重新读取**：实际为 `canvas_get(view:nodes, refresh:true)`，结果read/confirmed；核对节点ID、内容和版本。
3. **最后手动打开原生画布**：节点和图片与读回内容一致。所有“无需打开画布”用例在前两步保持画布面板关闭；最后才打开查看。

| 结果 | 如何判断 |
| --- | --- |
| created + runtime:ready | 画布已创建，当前服务可继续使用；保存真实canvasId |
| created + runtime:not_ready | 画布已创建，但服务未准备好；保留ID，恢复后操作同画布，不能另建来掩盖问题 |
| saved | 节点已保存；记录affectedNodeIds、version |
| read + consistency:confirmed | 当前读取可确认；详情版version可供后续写入使用 |
| read + consistency:unconfirmed | 可能存在草稿/待保存/未知状态；本次不算完整持久化验收通过 |
| assetRegistration:registered | 图片节点保存后资产登记成功；与saved分别记录 |
| saved + 登记rejected/registration_unknown | 节点保存已成功，登记闭环有问题；记录问题，不重新新增同节点“修复”登记 |
| needs_input | 缺图或缺明确产物选择；补信息后继续 |
| VERSION_CONFLICT / EDITOR_BUSY | 保留现有内容，先核对/完成编辑，不自动强写 |
| create_unknown / upload_unknown / submission_unknown | 结果未知；停止重复写入，保留轨迹/ID并核对现状 |

首次普通保存后节点数及内容应符合本次新增；没有其他修改时重载版本应一致。如果版本上升，先核对原生尺寸更新或其他实际写入，不能仅凭“不是严格+1”判失败；版本下降应记录问题。工具详情一次最多20个节点；内容/outputs截断时应明确报告，不伪称已读全。本轮小画布不需大数据测试。

正常验收不必打开DevTools或筛选Network。Host的创建/上传/登记请求不一定显示在Renderer Network里；筛不到请求不能单独证明失败。遇到问题再定向排查。不要把Token、Cookie或桥key粘贴到反馈中。

## 三、测试准备

1. 确认真实账号登录、alpha.10启用、Harness可正常对话。当前版本未变时无需重新安装。
2. 新建一个专用测试会话，关闭可见画布面板。准备一张普通聊天图片，可使用[蓝底黄色块测试PNG](evidence/task-4-test-image.png)。以图片附件方式提供，确认聊天中有图片预览。
3. 发送一次测试约束：

> 本轮只验收现有画布工具。不要修改项目代码，不要自行补工具，不生成图片、视频或音频，不打开画布。保存结果未知时停止并说明，不要重复新增。只有我明确要求新建或新增时才执行写入。

4. 下文A/B、T/I均是记录别名，不是工具接受的ID：A为第一张新画布，B为第二张；T为测试文本节点，I为聊天图片节点。涉及占位符时替换成工具返回的真实ID。

## 四、建议先执行的主流程

### M01 创建空画布并读取

目标：验证创建API、无界面服务初始化和可信读取。

> 创建一个叫“巩固验收A”的空画布，不添加节点、不生成、不打开画布。创建后从后端重新读取节点详情，告诉我画布ID、节点数量和当前保存版本。

预期：canvas_create返回created及真实ID；正常runtime:ready；canvas_get为nodes/refresh:true，read/confirmed、nodeCount:0。记录A。若创建已成功但准备失败，保留A并记录，不换画布重建。

### M02 新增文本，验证内容保存

目标：验证节点字段映射、严格保存和文字读回。

> 在画布【A的真实ID】新增一个文本节点，标题“中文文本测试”，正文为“通过Agent创建并保存；中文、标点、emoji ✅”。只新增保存，不生成、不打开画布。保存后从后端重新读取这个节点，告诉我节点ID、正文和保存版本。

预期：canvas_node_edit action:add/type:text；saved，一个新节点ID；重载同ID/标题/正文一致，节点数1。记录T。不要仅依据文本节点status判断“调用过模型”；本轮没有生成。

### M03 新增三类普通媒体节点

目标：验证image/video/audio原生构造、默认参数与提示词字段；不执行模型。

依次发送三条，等待上一条完成后再发下一条：

> 在画布【A】新增一个普通图片节点，标题“图片待生成”，提示词“蓝色桌面上的白色耳机”。使用原生默认参数，只保存，不上传图片、不生成、不打开画布。

预期：每次一条add且写前读取/采用可信当前版本，三类都只保存。原生默认配置可用时A共4个节点；提示词完整读回；媒体outputs应为空，无新生成产物。若某类型CONFIGURATION_ERROR，记录具体类型、工具结果及原生UI是否也缺默认配置；不要用另一个类型替代并声称通过。

### M04 聊天图片导入

目标：验证真实会话附件、Host上传、原生来源节点保存与资产登记。

预期：canvas_assets识别本条图片，canvas_asset_import source:attachment使用真实attachmentId；saved且一个节点ID；assetRegistration:registered；重载contentType:upload、同URL、generation:null。记录I。M02–M03均成功时A节点数5。图片素材URL通过Host生成，不要求Agent从本机路径或任意URL导入。

### M05 打开、关闭与原生显示

目标：验证原生UI显示和关闭面板后的读取。

1. 前四项完成后，手动用Shell画布ID控件打开A。
2. 对照工具结果检查实际节点ID/类型/标题、文本及三个提示词；“聊天图片素材”显示所附图片。普通图片/视频/音频是未生成节点，不能当作已生成素材。
3. 关闭画布面板；在同一会话发：

> 从后端重新读取画布【A】，核对“中文文本测试”和“聊天图片素材”的节点ID及内容。只读取，不打开画布，不新增节点。

预期：read/confirmed，仍是同ID/内容，节点数未增加，画布面板保持关闭。这里验收“关闭面板”，不是退出Shell。

### M06 已有画布图片复用

目标：验证任务4第二种素材来源，不依赖聊天附件仍可见。

> 创建一个叫“巩固验收B”的空画布。将画布【A】中节点【I】的现有图片作为新的图片素材节点加入B，标题“已有素材复用”。只复用保存，不重新生成、不打开画布。完成后从后端重新读取B，告诉我画布ID、节点ID、保存版本、素材URL和资产登记状态。

预期：创建B；canvas_asset_import source:canvas_node，来源canvasId=A/nodeId=I；asset.status:reused，新节点ID与I不同、URL与I相同；saved，登记registered，B一个节点；A不发生新增或修改。记录B及新节点ID。

### M07 多画布目标准确性

目标：验证Agent实际调用和服务路由使用指定ID，不随可见面板换目标。

手动打开B，再在测试会话发：

> 虽然界面现在显示另一张画布，请只在画布【A】新增文本节点，标题“指定目标A”，正文“这条内容只属于A”。只保存、不生成，不切换或打开画布。完成后从后端重新读取A和B，分别报告节点数量与该节点是否存在。

预期：真实工具写入canvasId=A；新节点只在A，B内容不变。各类型前面均成功时A从5到6，B仍1。打开A应显示新节点。若Agent工具入参误用B，属于意图/目标选择问题；入参为A但结果写进B，属于桥/上下文问题，分别记录。

### M08 原生手动修改与Agent后续操作一致

目标：验证复用原生Store/保存；Agent后续新增保留用户已保存的修改。

1. 手动打开A，将T正文改为“用户手动修改后的内容”，按原生UI方式结束编辑并等待保存完成。不要保持未提交草稿。
2. 关闭画布面板，发：

> 先从后端重新读取画布【A】中节点【T】，告诉我当前正文。然后只新增一个文本节点，标题“手工内容保留验证”，正文“这是新节点”。不修改或替代【T】，不生成、不打开画布。保存后从后端重新读取【T】和这个新节点，报告各自ID、正文及当前版本。

预期：read/confirmed返回T手动修改后的正文及同节点ID；只新增“手工内容保留验证”一个节点；随后权威读取T仍保留用户正文，没有恢复旧正文或新增替代节点。前面全部成功且未执行补充写入时，A从6到7个节点。此项证明UI保存→Agent读取/新增一致，不等同于已经命中“并发编辑拒绝”的测试。

## 六、保护与故障类测试的现实边界

### 活动编辑保护：可选观察，不把未命中当通过

在新的测试节点编辑器保持未提交草稿时，发送一次新增请求，并在Agent实际工具执行期间重新聚焦编辑器。记录工具结果、草稿是否保留以及原生UI是否受影响。若实际命中活动编辑，可能出现EDITOR_BUSY，详情读取也可能unconfirmed；完成编辑后再明确发起新请求。

发送聊天消息会改变焦点，操作速度也有竞争窗口。若工具执行时编辑已经结束、草稿已自动保存，则本次没有覆盖冲突路径；记录“未命中/未覆盖”，不能因为未见EDITOR_BUSY判保护失败，也不能作为并发保护通过证据。任务1.3有自动guard/原生队列证据；用户正常手测主要先验证M08不回退已保存内容。Agent更新已有节点当前未开放，因此不能用“Agent改同一段正文”手测更新保护。

### 版本冲突、重复运输、断线：问题出现后定向排查

- 普通对话中Agent会先读最新版本；仅靠重复发送prompt不能稳定复现队列内版本冲突。VERSION_CONFLICT发生时，应停止自动强写，保留用户内容，先读取核对；底层并发路径已有自动测试。
- 同callId/requestId的重复运输与新一轮相同prompt不同。重新发送“再加一个”是新请求，不能期望原调用去重阻止它。
- 不建议为了主流程手测中断上传或退出Shell。若自然发生create/upload/submission_unknown，记录原调用与ID，不重复新增；读回结果可以确认现状，但不能恢复所有网络事实。
- 当前未交付完整生成任务聊天反馈，不把“生成后Agent主动播报结果”作为任务1–4本轮标准。原生画布的生成/loading/监听能力仍由已有业务提供。
