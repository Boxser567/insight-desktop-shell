# 任务 1.4.2 实施与验收：原生上下文初始化与 readiness

日期：2026-10-12。本轮完成 1.4.2 编码与自动验收，沿用 karpathy-guidelines；未推进 1.4.3 Client 服务入口。后端、Shell / Core 业务、工具与 SSE 协议未改。

## 达成目标与当前边界

新增 createCanvasContext(canvasId)，持有 1.4.1 的真实 Store / barrier / guard。它不创建 DOM、iframe 或 CanvasFlow，不依赖 UI paint，能使用原 API 准备图、原始版本、模型、权限与订阅迁移，再调用原 Store.init 并等待已有持久化队列稳定。它分别报告 read / edit / run 能力与失败原因。

上下文默认没有编辑所有权，因此初始只能准备可读图、不自动保存。setOwnership 仅供后续原生所有权控制器内部调用，不是 Agent 参数；1.4.4 才接该控制器。测试通过内部调用模拟 active/inactive，不能据此宣称 Shell 已获得后台编辑资格。服务 ESM、Client registry、同源 UI 绑定、adapter 和生成 monitor 尚未实现；当前还不能通过 Agent 对话调用。

原 CanvasFlow 复用提取后的模型 / 权限加载函数；默认 UI 的加载顺序、catch 提示、只读预览、paint 后加载音色 / 价格、卸载 reset 和刷新按钮仍保持原路径。owned UI 取消二次 init/reset 与接入新刷新入口属于 1.4.4，本轮没有提前改造。

## 当前可供开发调用的接口

```ts
createCanvasContext(canvasId: string): CanvasContext;
context.initialize(capability: 'read' | 'edit' | 'run', signal?: AbortSignal): Promise<ContextInfo>;
context.reload(capability: 'read' | 'edit' | 'run', signal?: AbortSignal): Promise<ContextInfo>;
context.getInfo(): { canvasId: string; contextId: string; readiness: FrameReadiness };
context.getCanvasMetadata(): { name: string; temp: boolean; thumbnailUrl: string; templateId: string | number };
context.getInitialization(): CanvasInitialization;
context.subscribeReadiness(listener: (state: FrameReadiness) => void): () => void;
context.loadUiData(signal?: AbortSignal): Promise<void>;
context.setOwnership(status: 'checking' | 'active' | 'inactive'): void;
context.dispose(): void;
```

initialize 成功后重复调用读取当前能力，不重新请求图，不清未知保存。图 / 配置加载失败后通过显式 reload 恢复；不自动重试。Context ID 在 reload 中保持，epoch 使旧辅助 / 尺寸响应失效。readiness callback 不拥有业务结果；观察者异常记录到 console，不让通知失败污染严格保存回执。

每个等待者的 signal 只停止自己的等待；context dispose / auth invalidation 中止共享准备。dispose 会禁止新操作、清理订阅与 auth listener、失效媒体请求和未发队列项；不承诺撤回已发送 HTTP 请求。请求 signal 和回调是可信本地参数，不交给模型或后端。

loadUiData 复用原 fetchTone / getAllRule，按需加载且同 epoch 去重，不等待 paint。普通文本和图读取不为音色 / 价格等待。账户积分余额不是这里的价格表；point API 与生成 monitor 在后续步骤组合，没有新增替代实现。

```ts
const context = createCanvasContext(canvasId);
const info = await context.initialize('read'); // 无需打开画布
const snapshot = context.store.getState();
// 后续所有权控制器确认 active 后，若曾以只读方式初始化，先显式权威 reload。
// 不允许 Agent 自行调用 setOwnership。
context.dispose();
```

目前 registry 尚不存在，因此同 ID 的多次 createCanvasContext 会创建多个独立对象；并发去重仅限同一个 context.initialize。1.4.3 必须由 registry 保证每 Client / canvasId 只创建一个 context，不能让每条 Agent 命令直接调用工厂。

## 判断规则与后续调用约束

- 模型权限成功空数组沿原语义为 null，表示未启用额外前端限制；工具权限成功空数组为 {}，表示工具白名单为空。加载失败也可能落到 null，但阶段为 failed，绝不能只看 null 当作成功。
- 模型 SUCCESS + 合法空对象记录 ready/empty:true，生成能力为 false；模型解析 / 权限请求失败记录 failed。订阅 CDN 失败沿原空映射策略记录 fallback，不宣称模型替换成功。真实 native init 返回的替换结果保存在 graph.replacedSubscriptionModel。
- run 能力只是配置与基础写资格的粗粒度判断；没有生成提交或 monitor。1.4.6 adapter 必须继续按节点类型、字段和实际权限检查；媒体参数修改 / 创建生成节点需检查配置阶段，不能因 edit:true 就放行。text 普通内容修改 / 删除只要求实际需要的能力。
- 无可信版本不自动保存，readiness.version 为 null；合法数字 0 与大 Long 字符串原样保留。严格操作不以本地 +1 推算版本。
- init 的已有媒体保存被等待并观察 persistence issue。未来仍可能出现尺寸结果，继续原队列 / barrier；不是等待所有未来异步尺寸探测才 ready。
- 未获所有权时 read=true、edit/run=false；获得所有权后，对之前只读准备的图必须权威 reload。所有权竞争 / query / claim 与跨窗口行为尚未接入，由 1.4.4 实现。
- reload 拒绝已有 guard busy、草稿和队列内 / coordinator 中的待持久化任务，不 flush / blur。owned UI 的尚未入队异步新增 / 上传准备，需在 1.4.4 接 UI 时一并验收，不能仅凭本项 hasPendingMutations 当作所有 UI 活动的检测器。
