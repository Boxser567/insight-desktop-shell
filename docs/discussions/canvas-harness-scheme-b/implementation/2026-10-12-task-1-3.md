## 必须保持的原生行为

原 prompt / 文本 / 音频防抖并未在组件卸载时取消，会继续提交。直接清标记会让延迟提交撞上 Agent，取消则可能丢最后一次输入。因此这些待执行回调及其标记保留到原 callback 入队后清除，不新增卸载自动 flush。原有滑块卸载 flush 和返回原值时 cancel 保留；纯数字输入草稿在控件卸载时按原行为舍弃并清理标记。

这是对旧计划“cancel / unmount 清理”的具体修订：**尚会执行的原生 callback 不能被当作已取消**。标记属于每一个 debounce 实例，旧实例提交 / cancel 不会清掉同节点的新实例。IME 标记与 debounce 标记独立；compositionend 不能清掉仍未提交的防抖。移除编辑器、Canvas 卸载时只清 DOM 组合 / gesture 标记，不忘掉仍会执行的原生持久化。

保护仅在传严格 options 的 Store 路径启用；原 UI 默认 actions 返回、toast、debounce 和媒体更新保持原路径。root 锁通过 DOM 阻止新手工动作，允许系统更新 Store；它不把 Store 切成 readOnly。焦点仍在 input / textarea / contenteditable 时采取保守拒绝，即使该值尚未改变，也不会 Agent 主动 blur 或 flush。
