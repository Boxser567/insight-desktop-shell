# alpha.12 按序可复制的真实账号手测

本轮只编辑、配置和保存。当前账号插件已用现有官方安装方法升级至alpha.12，58个安装文件匹配，bundle及组件启用配置确认；无需重复导入。当前客户端的实际加载和新会话工具目录仍待只读核验，先重启Harness（⌘⇧R）并新建对话。记录见[evidence](evidence/2026-10-13-alpha12-account-install.json)。包：`/Users/boxser.shi/Documents/harness/desktop-canvas-plugin/insight-ai-desktop-canvas-plugin-0.3.0-alpha.12.tgz`。

P01附一张商品图，之后保持同一对话，前9步不打开画布。每一步以实际工具回执和回读为准，失败停在该步反馈；submission_unknown不能自动重复写入。本册是此前G01–G06的细化，其中排序改用两个独立图片节点来验证同类输入顺序。

## P01 创建三节点（附商品图）

```text
开始alpha.12真实账号手测。整个测试只使用当前画布工具编辑、配置和保存，不编写或执行代码，不触发文本/图片/视频模型生成，不执行模板，不自动打开画布。每次写入使用最新confirmed版本，成功后回读核对；出现rejected或submission_unknown时停止当前步骤并报告实际回执，不自动重复写。

先确认canvas_edges和canvas_models已在本对话加载；缺少则报告并停止。创建一个叫“alpha12图编辑验收”的新画布，添加“头部文案”文本节点，正文为“轻巧随行，听见更多”；把我附上的商品图导入为“耳机原图”图片素材节点；添加“头部卖点图”空图片生成节点。输出实际画布ID、三个节点ID、最新保存版本及节点回读结果。后续都操作这个新画布。
```

验收：3节点、0边；原图contentType为upload且outputs含图片URL；卖点图outputs为空。真实created/saved回执，画布未打开。名称和正文为测试用固定内容，不要求Agent创作文案。

## P02 修改字段

```text
在刚才的测试画布中，用canvas_node_edit(action:update)将“头部文案”的标题改为“头部文案-V2”，正文改为“通勤轻负担，音乐随身听”；将“耳机原图”标题改为“耳机参考实拍”；将“头部卖点图”的prompt设置为“保持参考商品外观，使用简洁背景，预留标题区域”。只修改和保存。回读三个节点，报告实际ID、变更字段和各次保存版本，并核对原图URL、contentType及尺寸是否保持。
```

验收：同一批3节点ID不变；文本标题/正文、目标prompt生效；上传原图仅标题改变，URL/contentType/尺寸保持。目标仍无产物。

## P03 两条真实连线

```text
读取测试画布的真实图结构和端口。用canvas_edges(action:add)将“头部文案-V2”接到“头部卖点图”的文本输入，将“耳机参考实拍”接到它的图片输入，依次使用最新版本保存。再读graph和目标节点详情，列出两条边的真实ID、source、target、sourceHandle、targetHandle及目标inputs。将原图到目标的这条图片边ID记住，后面要改接。
```

验收：3节点、2边；graph.edges与目标inputs的edgeId对应，端口类型正确。outputs中的URL不是边。此时默认模式与图片输入不匹配出现warnings可以接受。

## P04 合法模型配置

```text
调用canvas_models查询当前账号可用图片模式、模型及标量参数。给“头部卖点图”选一个支持参考图的图生图模式及可用模型；画幅优先1:1，gen_count优先1，均使用目录真实value及其原始类型。如果方图或数量1不可选，采用合法可用值并说明；没有参考图模式则报告本步骤无法验收，不猜模型。用canvas_node_edit(action:configure)保存，随后回读该节点实时params、paramHints、尺寸、inputs和outputs，报告实际保存版本。只配置，不提交生成。
```

验收：查询在先，保存使用当前有权限的真实模式/模型/参数；空节点尺寸符合所选画幅，outputs为空。无参考图模式属于账号能力条件，此项标未验，可继续节点/边测试。目录paramHints描述默认父参数组合，保存后的实时选项以节点详情为准。

## P05 第二个独立图片节点

```text
通过canvas_asset_import复用当前画布“耳机参考实拍”的已上传图片，导入为一个新的独立图片素材节点，标题“备用参考图”。不需要另传图片，不用生成来复制图片。本步只新增这个素材节点并保存，先不连接。报告两个图片节点的真实ID、outputs、保存版本和当前节点/边总数。
```

验收：4节点、2边；两个素材节点ID不同，复用同一图片URL；原节点保留。复用同图足以检验结构顺序，不用于比较图片视觉差异。

## P06 改接并保留边ID

```text
读取真实图，找到P03建立的“耳机参考实拍”到“头部卖点图”图片边。必须使用canvas_edges(action:reconnect)，把其source改为“备用参考图”，target仍为“头部卖点图”，沿用合法图片端口。不要用删边再加边替代。保存后回读，列出改接前后边ID、端点、handles、目标inputs和保存版本。
```

验收：仍4节点、2边；图片边ID完全不变，source从原图改为备用图；文本边及所有节点保持。

## P07 新增第二条图片入边并排序

```text
先用canvas_edges(action:add)将“耳机参考实拍”重新连接到“头部卖点图”的图片输入，形成两条来自不同图片节点的入边。保存并读取目标的全部三条入边。

随后使用canvas_edges(action:reorder)，提交这三条真实边ID的完整顺序：第一为“耳机参考实拍”的图片边，第二为“备用参考图”的图片边，第三为“头部文案-V2”的文本边。使用新增后的最新confirmed版本，不通过删边重建排序。输出新增和排序两个实际保存回执，并列出排序前后graph.edges及目标inputs的有序edgeId/source节点ID。
```

验收：4节点、3边；图片输入从“备用、原图”变为“原图、备用”，原来的两条边ID保留，新加边有新ID；目标inputs顺序与图中目标入边顺序一致；节点位置不变。只把图片放在文本前面不足以证明同类素材排序，此处必须看两条图片边的顺序翻转。

## P08 只删除连线

```text
找到“头部文案-V2”到“头部卖点图”的文本边，用canvas_edges(action:delete)仅删除这条边并保存，保留文本节点及其正文。回读graph和目标inputs，报告被删除的真实边ID、affectedEdgeIds、保存版本及剩余节点/边。
```

验收：4节点、2条图片边；文本节点仍在且正文不变，仅文本边消失。

## P09 删除节点并清理关联边

```text
用canvas_node_edit(action:delete)删除本测试画布中的“耳机参考实拍”素材节点，保留“备用参考图”“头部卖点图”和“头部文案-V2”。保存后回读graph及保留节点，报告affectedNodeIds、affectedEdgeIds和保存版本。核对原图重新连接的那条边随节点删除，P06改接到备用图的原图片边仍保留原ID，目标的模型参数和prompt没有改变。
```

验收：3节点、1边；删除节点及其入/出关联边被原生清理，剩余边是P06改接后的稳定ID，source为备用图。仍有参考图时，不要求出现缺图warnings。

## P10 权威重载与界面核对

```text
本步仅核对：对本测试画布调用canvas_get(view:graph, refresh:true)从后端权威重载，再用view:nodes读取三个剩余节点详情。报告重载前后版本、consistency、节点总数、完整真实边列表、文案正文、图片素材URL，以及“头部卖点图”的prompt/modelType/model/params/outputs。核对P02、P04、P06–P09结果是否持久化。保持画布未自动打开，不执行生成，不修改代码。
```

验收：confirmed；3节点、1边及稳定ID保持；文本/模型/prompt等保存内容保持；目标outputs为空。之后由用户首次打开画布检查真实线、剩余节点、参数和位置，再关闭。工具回执与UI实际状态均应一致。

补充：配置后的generation.images可能为1，表示计划张数，不是已完成产物数。以outputs为空、没有执行工具/新生成任务作为未生成依据；上传素材outputs原本有URL属于正常。
