## 实际接口与执行位置

```ts
canvas_assets({});
canvas_asset_import({canvasId,expectedVersion,
 source:{type:'attachment',attachmentId}
   |{type:'canvas_node',canvasId,nodeId,outputIndex?},title?,position?});
// 内部Host→Client operation
{action:'asset.add',expectedVersion,asset:{url,title?,position?}};
```

`canvas_assets`仅列当前模型可见用户消息中的图片引用，按最近出现排序去重，最多20条，包含总数/截断/归一化说明；无图返回needs_input。Host从真实 `exec.agent.session.deriveMessages()`取完整ImageAttachmentRef，再调用 `ctx.attachments.readImage(ref,signal)` 验证字节。模型不能指定会话、凭证、文件路径或任意URL；外会话ID在读取前拒绝。文件附件原始字节和会话压缩后不可见的旧图本期未接入。

import先准备目标并核对expectedVersion，之后解析明确素材。聊天图片由Host复用原生STS规则、命名、ObjectKey、公开URL及上传政策，使用Node OSS SDK单次PUT；已有画布图片来源需经原v3桥confirmed读取真实image节点outputs，多产物未指定序号则收集缺项。上传后再次核对账号/环境，再用同一桥提交asset.add。

Client服务复用原生 `util.createNode`、`buildMediaUploadNodeData`、`actions.addNode(factory,strictOptions)`。图片成为 `data.type:upload/value:URL/product:[]/tempFile:null` 的纯来源节点；标题、尺寸、编辑保护、版本队列与严格回执仍由原有方法处理，不要求可用生成模型，不增加iframe或另一个Store，不修改原UI。现有详情已能返回contentType/outputs/generation:null，无需扩媒体读取字段。

saved之后Host固定调用原 `upload/asset`，显式传canvasId/nodeId、assetType1/source0/sourceType upload，返回独立assetRegistration。身份/STS/登记分别复用当前desktopToken，Long ID按原数字wire无损发送，不转不安全Number。工具输出保留JSON字符串；原create/get/add三工具保持。

## 失败、去重与Review判断

调用回执按真实session/callId及完整规范化参数去重；相同调用并发只写一次，参数变更拒绝。上传复用按环境/账号/会话/附件隔离，缓存与在途沿任务2的1024/8上限；不驱逐未知写回执来再次发出。插件卸载取消后续流程；发出后的OSS请求不承诺撤回，未确认则明确unknown，不添加新节点。

身份GET或STS获取失败时，PUT尚未开始，不能误报上传未知；明确OSS HTTP4xx（除408）是拒绝。PUT网络丢失/408/5xx/畸形成功/发出后取消为upload_unknown/never_auto。上传已确认而画布保存拒绝，保留asset引用，后续明确操作可复用上传；保存unknown保留原生节点ID及屏障，先读取核对，不自动重加。节点saved后登记拒绝/registration_unknown仍保持saved及真实节点ID，不回滚、不重新新增。

Review通过先红后绿修复了身份body响应、前置失败分类、合法业务CDN登记、裸fragment/空白URL、明确PUT拒绝分类。当前SDK0.1.6开发包与Cordis4.0.5-alpha.1存在peer冲突；开发SDK统一到实际Core0.2.1-alpha.1解决，未force/legacy-peer-deps，未升级Web业务库。首次Web全回归的pnpm子进程误用全局Node导致jsdom ESM错误；固定PATH为Shell Node24.9后同一回归182通过，没有绕过测试。
