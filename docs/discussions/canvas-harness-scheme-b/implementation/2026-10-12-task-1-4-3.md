## 本步实际能做什么

插件 Client.apply 通过独立 ctx.effect 安装 window.__INSIGHT_CANVAS_RUNTIME_V1__。这个 handle 不属于标签页或 conversation slot；首次访问 ready 才从同源固定路径 /desktop-canvas/canvas-service.js 加载 ESM 服务。加载模块、创建 runtime 都不创建画布上下文；ensureContext 按 canvasId 创建并缓存真实 1.4.2 context。

同一个 Client / canvasId 的并发 ensure 共用同一 context ID 与一次初始化；不同 ID 隔离。初始化失败保留该 context，ensure 不自动重试，显式 reloadContext 才重新准备。readiness 订阅只针对已有 context，未知 ID 不隐式创建。Client 卸载会停止等待 import、禁止迟到模块创建 runtime、清掉自己的 handle 并 dispose 全部 context。

本步仅开放实际实现的 CanvasServiceRuntimeBase 六个方法，没有 execute、view binding 或假成功占位。上下文仍默认 checking ownership，因此可准备 read，edit/run 仍须 1.4.4 所有权控制器与后续 adapter / monitor。Agent 调用尚未接通。

## 当前接口与错误

```ts
interface CanvasContextInput {
  canvasId: string;
  capability: 'read' | 'edit' | 'run';
  signal?: AbortSignal;
}
interface CanvasServiceRuntimeBase {
  ensureContext(input: CanvasContextInput): Promise<CanvasContextInfo>;
  getContextInfo(canvasId: string): CanvasContextInfo | null;
  subscribeReadiness(canvasId: string, listener: (state: FrameReadiness) => void): () => void;
  reloadContext(input: CanvasContextInput): Promise<CanvasContextInfo>;
  closeContext(canvasId: string): Promise<void>;
  dispose(): void;
}
interface CanvasRuntimeHandle {
  readonly ready: Promise<CanvasServiceRuntimeBase>;
}
```

ContextInfo 沿用 canvasId / contextId / readiness；不是 iframe ID。未知 info 返回 null；未知 subscribe 返回空 disposer，close 幂等；未知 reload 返回 FRAME_NOT_READY。预取消不创建 context。readiness / reload 的真实业务判断继续由 1.4.2 执行，不重复维护另一份 ready 状态。

加载失败、缺 factory / 方法或卸载后访问 handle 为 CLIENT_UNAVAILABLE；重复安装为 CLIENT_AMBIGUOUS；服务已 dispose 为 FRAME_GONE。close 的 busy 为 EDITOR_BUSY，RUNNING 为 NODE_BUSY，持久化 issue / 版本问题保留原错误码。业务错误含 not_sent，表示该次服务调用未发出 Agent 修改 / 生成命令，不否认已有初始化或原生保存请求。

factory 创建的 registry 不暴露原始 context / Store / setOwnership 给 handle。后续 view binding 与 execute 在同一 registry 内组合，不从 iframe 或每条命令重新创建另一份可写 Store。

## 开发者手动验证入口

下列是真实 Harness Client 窗口的开发验证步骤，需使用已构建 / 安装本期插件的隔离环境并已在 Shell 登录；不在 Canvas iframe 或本讨论文档的浏览器页执行。本轮未对真实 Shell 浏览器执行这些步骤。

1. 不打开画布，确认当前 DOM 中没有 `/desktop-canvas/view` iframe；Client apply 后应已有 handle，但尚无服务脚本加载和业务取图请求。
2. 在该 Client 的 DevTools 访问 ready，再使用一个实际有权限的 canvasId：

```js
const service = await window.__INSIGHT_CANVAS_RUNTIME_V1__.ready;
const canvasId = '替换为真实画布ID';
const info = await service.ensureContext({ canvasId, capability: 'read' });
```

3. Network 应有固定服务路径（带 runtime 查询标识）和共用 chunk，之后才出现原图 / 模型 / 权限 API。没有新增画布 view / 隐藏 iframe。再次并发 ensure 同 ID，contextId 应相同，取图不重复。
4. 当前 read 能力可用，edit/run 在所有权未接入时应被拒；不要在 Console 强行 setOwnership 或将这种拒绝误报为任务已生成。
5. 对非 RUNNING、无 unknown 的闲置 context 调用 closeContext，再 ensure 应产生新 contextId；有保存 / 草稿 / RUNNING / unknown 时 close 应拒绝。
6. 关闭普通面板不应移除 handle。仅在隔离环境卸载插件 / 销毁工作区时，handle 被移除，旧 runtime 不能复用，迟到 import 不能重新安装。实际账号工作区生命周期与 CSP 由 1.4.8 一并烟测。
