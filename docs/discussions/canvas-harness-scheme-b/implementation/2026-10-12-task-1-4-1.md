# 任务 1.4.1 实施与验收：每画布工厂与隔离

日期：2026-10-12。本轮完成 1.4.1 实际编码与自动验收，遵循 karpathy-guidelines；止于工厂层，没有推进 1.4.2 初始化。后端、Shell / Core 业务、通信协议、模板与模型配置均未改。

## 本步达到的目标

同一插件进程可以创建多个独立的原生 Store。A 的图、模型表、历史、版本、只读、持久化异常、轮询 barrier、编辑草稿与严格操作锁不会影响 B。同一 Store 内继续使用原 mutationQueue 与媒体协调器，每条严格操作只取得一次 guard；没有新增持久化实现。

原生 UI 仍使用默认 Store 与默认 barrier / guard，保留 hook、getState / setState / subscribe / getInitialState、方法返回值、只读标志、toast、容量弹窗、撤销与持久化行为。新增工厂默认不弹 UI 提示；反馈和旧全局只读同步由调用方注入。容量弹窗改为按需 import 同一个原生实现，以解除工具模块对路由 / UI bootstrap 的提前加载。

这只是“无需打开画布”的前置改造。当前尚无 context registry、ensureContext、初始化 readiness、UI 同源绑定或 Agent 工具；新 Store 初始仍没有 canvasId / 图 / 版本，不能把工厂成功创建当作画布业务已就绪。

## 当前开发接口与复用方式

```ts
createFlowStoreApi(options?: {
  barrier?: CanvasVersionBarrier;
  guard?: AgentEditGuard;
  feedback?: {
    error?: (message: string) => void;
    showCapacityLimit?: () => void | Promise<void>;
  };
  onReadOnlyChange?: (readOnly: boolean) => void;
}): FlowStoreApi;
createCanvasVersionBarrier(): CanvasVersionBarrier;
createAgentEditGuard(): AgentEditGuard;
```

未传 guard / barrier 时各自创建新实例；后续 context 应创建并注入实例，以便 monitor / view / adapter 共用同一套对象。onReadOnlyChange 仅用于原 UI 同步旧全局标志；新 context 不应注入旧全局 setter。feedback 是本地回调，不进入后端 HTTP body。

```ts
const guard = createAgentEditGuard();
const barrier = createCanvasVersionBarrier();
const store = createFlowStoreApi({ guard, barrier });
// 后续 1.4.2 才会通过原 API 准备图、模型、权限和版本。
// 初始化完成后，严格写仍调用原 actions；外层不要重复取得同一 guard。
await store.getState().actions.updateNodeData(
  nodeId, { title: nextTitle }, true, true,
  { strictReceipt: true, expectedVersion }
);
```

guard 暴露 markEditorBusy、isEditorBusy、isOperationBusy、subscribeBusy、subscribeEditors、assertOperationActive、run、attachRoot(viewId, root)、dispose。新实例无视图时不检查全局 document 焦点；detach 幂等，只清该视图 DOM 状态，不清仍会执行的持久化草稿。dispose 使等待中的未发送操作返回 READ_ONLY/not_sent，不承诺取消已发送 HTTP 请求。

默认导出函数仍绑定旧兼容实例：继续检查全局 document 焦点、在 iframe 卸载时使旧严格操作失效。现有控件和 debounce 仍用它们；将这些控件绑定到 context 属于 1.4.4–1.4.5，本轮没有迁移。

barrier 暴露 runPolling、beginMutation、waitPollingIdle、consumeUncertain、isUncertain。saveCanvas / partialUpdate 的末尾可选 readOnly 参数默认读取旧全局标志；新 Store 总是传自身 getState().readOnly，避免 A 的标志干扰 B。原数据序列化、API 地址、strictReceipt、requestPhase 和版本校验规则未改。
