# 从最小对话入口扩展到画布主要业务能力

日期：2026-10-13。本文件保留alpha.10时的范围复核与推进建议，以下“当前”表格按当时版本理解。

最新更新：基础图编辑阶段已在alpha.12完成编码、review、插件172/Web266、构建和实际Core隔离七工具验收；真实账号图编辑待G01–G06反馈。已开放普通节点修改/删除、真实连线、完整图分页和合法模型配置，继承alpha.11自动放置。生成执行、抠图接入、工具创建和模板/Skill仍未开放，后续先验收该阶段再做产物闭环；任务5、6和完整版Skill继续暂缓。详见[alpha.12实施](../implementation/2026-10-13-agent-graph-edit.md)及[手测](../implementation/2026-10-13-agent-graph-edit-live-acceptance.md)。

## 1. 修订目标与原因

目标是让Harness Agent驱动成熟画布的主要业务：创建与编辑节点、配置入参、建立真实关联、执行已有业务、获得结果，并能局部修改和重跑。无需用户先打开画布；可随时在原生UI查看或继续编辑；复用已有后端、Store、保存队列、工具API和生成监听。

此前任务2/3为最小实账验收，缩小到读取/普通节点新增；任务4补图片素材。原总体任务3曾包含节点修改和canvas_run，但后续推进顺序没有显式补回完整图操作、连线及专用工具接入，就直接指向场景包5/6。这不足以实现用户期望的主要业务掌控，应先补公共能力，再做模板和Skill。

用户实际反馈：创建耳机详情页画布、文案节点和导入耳机原图后，要求抠图、文案+产品生成头部卖点图并建立关联，当前Agent工具无法继续。反馈中的节点ID/结果片段仅用于说明，不作为本轮新业务执行证据。

## 2. 已核对事实与误判修正

| 用户会话中的判断 | 源码核对结论 |

| 原生画布没有抠图，需要新抠图库/模型 | 不成立。已有autoMatting调用/image/matting，图像编辑器使用返回的mattingImageUrl；没有独立matting节点类型，但有现成抠图子功能 |

| inputs/outputs都是空，画布没有关联能力 | 字段语义混淆。inputs来自真实入边；outputs是媒体URL，不是出边。当前没有建立边，不说明原生连线方法不存在 |

| 第二步可以立即继续生成详情页素材/完整长图 | 当前工具不能执行，Agent应把它标为创作建议及待开放能力，不能承诺“选一个就开工” |

## 3. 原生能力、当前入口与接入缺口

原生[节点注册表](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/components/canvasFlow/index.tsx:120)共有20种：4种普通媒体、group及15种工具。工具包括姿势生成、高清图片、图像编辑器、图像分层、文本重绘、高清视频、多视角、数字人对口型、姿势迁移、音频裁切、视频裁切、扩图、局部重绘、分镜、全景图。宫格裁切也是现有工具操作，但不是这里的独立注册节点类型。

“当前只可新增4/20类节点”是类型创建范围的比较，不能当作业务覆盖率20%；一个image节点还包含模式/参数/生成/编辑/引用等多项能力。

| 业务类别 | 原生已有 | 当前Agent | 下一步接入内容 |
| --- | --- | --- | --- |
| 画布创建与读取 | 有 | 创建、有限详情读取 | 保留；补完整图结构/边读取和分页，当前nodes每次最多20项 |
| 普通节点新增 | 有 | 4类型新增 | 保留原生默认配置及校验 |
| 普通节点修改/删除 | 有；adapter已有 | 未开放 | 补Host工具、bridge操作与回执，复用updateNode/deleteNodes及guard |
| 连线与输入顺序 | connect/connectMany/deleteEdges/edgeOrderChange | 未开放 | 加严格队列版本/保存回执；复用端口类型/数量/去重/校准规则，不开放任意setEdges |
| 模型、模式与参数 | 动态业务配置、权限、迁移规则 | 部分新增标量参数；模型/模式禁止 | 按当前配置按需读取与选择；模式变化后用原生参数迁移和连线规则，不能直接覆盖params |
| 普通节点运行 | excuteSingle；adapter已有node.run | 未开放 | 增加run能力、submitted/taskId回执及完成/失败反馈 |
| 普通选区/组/模板运行 | excuteTemp/excuteGroup | 未开放 | 明确执行范围、真实数量、严格版本与原生依赖；补批量确认 |
| 自动抠图等工具操作 | 有业务API/组件逻辑 | 未开放 | 抽取并共享现有操作、结果节点与保存方法，逐类适配 |
| 图片素材 | 原生上传与工具输出 | 聊天图片、已有画布图片复用 | 保留；清楚区分资产元数据与生成参数、工具结果节点ID |
| 视频/音频素材 | 有原生业务 | 未开放导入 | 逐步按现有上传策略及附件契约接入 |
| 状态与中断 | 无界面monitor、interruptWorkFlow | 只读状态；无完整任务事件/中断工具 | 复用监听，把任务事实推送到聊天；中断是请求，不等于立即停止 |
| 复制、分组、布局、模板 | 有Store方法 | 未开放 | 按高频业务清单接入；场景包和Skill在通用能力之后 |
| 精细画布/编辑器交互 | 蒙版、图层、拖拽、文字排版等 | 未开放 | 可程序化操作需明确mask/区域/图层/坐标输入；自然语言缺少定位时收集必要信息或交给原生UI |

复用入口：[原生Store动作声明](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/store/flowStoreCore.ts:192)、[原生边方法](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/store/flowStoreCore.ts:1179)、[普通运行](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/store/flowStoreCore.ts:1294)、[既有Agent适配](../../../../../desktop-canvas-plugin/canvas-app/src/agent-adapter.ts:35)。

## 4. 扩展原则与可达到的范围

对有明确输入/输出、能调用现有方法的原生业务，可逐步提供与UI等价的Agent调用入口。80%以上高频核心业务是合理的交付目标，但当前没有经定义和验收的覆盖分母，不能声称已达到某个百分比，也不能保证一个通用run工具覆盖所有原生工具。

每项能力贯穿：能力发现→明确输入→合法配置→严格保存→真实执行→结果保存/溯源→读取与局部修改。只支持建出一个工具节点，不算该工具完整可用。

1. Agent决定用户要什么、目标节点、业务范围及必要追问；原生业务方法负责端口、模型权限、参数合法性与保存，不让模型直接改Store或猜API。
2. 服务始终在已有插件执行。Host仍做授权/路由与素材处理；Client无界面服务复用原生Store、工具方法和monitor。不能改已安装node_modules来完成用户创作任务。
3. 通用能力目录必须区分“原生存在”“Agent已接入”“当前账号可用/未知”和缺失条件；从真实配置输出按需详情。完整业务Skill不是能力目录的替代品。
4. upload/tool读接口明确为非生成素材。实际尺寸/格式有可信元数据才报告；默认生成参数不得被解释成原图尺寸。保留原生UI/数据行为。
5. 执行仍用现有业务；SSE只传已有状态事实。原画布monitor继续原有监听，Agent不另外轮询。submitted只表示提交，生成成功须有实际产物。
6. 用户确认阈值沿用已约定：一次超过30张图片或6条视频时收集真实确认；不能靠模型传confirmed=true绕过。普通小范围生成不增加付费确认。
7. 原生Tool当前不支持一键执行混合DAG，见[原生检查](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/components/canvasFlow/utils/util.ts:1314)。工具应调用专用操作；先完成并保存输出子节点，再执行普通下游。首个耳机用例只需两段真实调用，不先建设新调度器。

## 5. 建议调整后的推进顺序

下面是前移的能力补齐阶段，不冒充任务5/6已经开始，不撤销任务1–4成果。

### 阶段一：基础图操作与普通生成闭环

前置修复已完成编码：alpha.11按用户限定实现auto/absolute/after坐标契约、原生尺寸准备后放置和严格新增保存，见[实施记录](../implementation/2026-10-13-agent-placement.md)。插件153/Web207、包及隔离检查通过；真实账号安装与坐标手测待用户反馈。旧UI位置行为保持，after延展可允许附近重叠，不做全图排版；后续局部layout工具和生成后校准尚未开放。

1. 能力目录与图读取：输出可调用动作、可用类型/模式/参数、端口与素材语义；明确区分图边和产物，补分页/按目标子图读取。
2. 节点CRUD补齐：桥与Host开放普通节点更新/删除；写入复用已有strictReceipt、队列版本、编辑保护；参数切换遵循原生方法。
3. 边操作补齐：新增/删除/改接与顺序，复用connect校验；补原生方法的strict options和可信保存回执，UI旧调用保持默认行为。批量返回成功/失败事实，不声称旧后端提供原子事务。
4. 普通运行及状态：桥开放run与submitted回执，Host注册真实执行入口，任务事实由原monitor/SSE传到对话；可按明确范围修改后只重跑目标。

验收：原图+文案连接到图生图节点→只生成1张→真实结果落回同画布→改一句文案并重跑该图；原图、其他节点不被覆盖或重新生成。步骤一到四均复用现有业务，不以外部生成再导入替代。

### 阶段二：以耳机案例开放已有自动抠图

1. 先接imageEditorTool的自动抠图操作，不新增独立matting节点类型。业务别名“抠图”可映射为已有工具的一项操作。
2. 把autoMatting及原生工具结果处理提取为UI/Agent共用方法；无可见画布时也能调用，结果入库、保存和关联完整。
3. 工具结果按原生结构写为image/tool子节点；回执明确toolNodeId/outputNodeIds。不是给工具本体随意加source handle。
4. 抠图结果保存确认后，再调用普通图生图节点；需要精细mask时声明必要输入，不让Agent猜蒙版。

建议真实图结构：

```text
耳机原图 image/upload
  → 图像编辑器 imageEditorTool（自动抠图操作）
    → 抠图结果 image/tool ──┐
                         ├→ 头部卖点图 image（图生图）→ 实际生成产物
小红书头部文案 text ───────┘
```

[工具节点保存回写](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/components/canvasFlow/customNode/tool/ImageEditorTool.tsx:108)、[工具输出子节点](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/components/canvasFlow/hooks.ts:1001)可复用，但目前位于组件/Hook，必须抽为共用服务并接strictReceipt，不能仅通过工具enum实现无UI运行。

验收：输入真实耳机图→真实抠图→同画布溯源与结果图→文案和结果图真实连入目标→生成1张→聊天报告实际状态→原生UI核对；更新目标文案后只重跑头图，原件与抠图结果保留。

### 阶段三：扩展高频业务并衡量80%

逐类接入高频工具、视频/音频素材、组/选区执行、中断、复制/分组/布局和节点引用。每类业务都复用自己的方法；外部异步任务、前端裁切与编辑器操作不能假装一种invoke。

通用能力稳定后，再恢复任务5场景包和任务6 Skill/模板工具。它们负责匹配业务场景、默认配置和复用已有能力，降低交互次数；不再承担弥补节点/连线/运行缺口的角色。

## 6. 80%怎样验收

先与实际产品需求确定高频业务清单及权重，例如：基础图操作、普通生成与参数、图片处理、视频/音频、模板/范围执行、素材管理、编辑恢复/中断。权重此时未设定，不制造百分比。

覆盖率 = 已通过完整业务验收项的权重之和 / 约定清单总权重。

基础连接、输入绑定、保存和生成链路是必须通过的门槛，不能被其他项目数量冲抵。源码存在、工具名称存在或能创建空节点，均不能作为完整验收通过。保留三种状态：原生已有但未接入、Agent接入但待实账、真实业务通过。

范围说明：目标按高频业务流程衡量，不把每个UI按钮等权计算。精确手工涂抹/自由图层编辑须定义可自动化输入后才能计入，不承诺自然语言自动覆盖100%像素级操作。

## 7. 本轮交付与下一步

本轮只读源码核对并修订方向。当前alpha.10没有新增操作，用户现有图未改动，后端不改，任务5/6继续暂缓。

下一步建议为阶段一写可直接开发的专项计划，列共享协议、Host工具、Client适配、原生边方法strict扩展、monitor/SSE反馈与每步验收；以耳机案例作为连续验收目标。自动抠图在阶段二接入已有业务，而不是重新研发抠图模型。具体账号可用模型、目标图合法画幅和抠图权限在执行前通过原生配置确定，不采用旧模板参数。
