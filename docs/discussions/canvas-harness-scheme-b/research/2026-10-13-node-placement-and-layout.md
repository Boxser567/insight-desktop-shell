# Agent新增节点的坐标、防重叠与原生排版

日期：2026-10-13。状态：只读源码调研与后续设计建议，未修改业务代码、未运行真实排版、未更新插件。用户已同意先补通用画布能力；本研究把新增节点防重叠补为前置事项，任务5/6与完整版Skill继续暂缓。

后续实施：用户限定不处理所有旧布局冲突、沿锚点延展可遵循附近规则。alpha.11已实现默认auto、absolute、after及原生严格新增集成，见[实施记录](../implementation/2026-10-13-agent-placement.md)。本文保留当时调研与更广泛后续建议；全图/局部layout工具、组内插入和生成后校准未在此次开放。

## 1. 结论

需要新增一个**插件服务内的统一放置计算入口**，用于单个新节点与一批新节点；已有一键排版的纯算法可以复用。

默认策略分两层：

1. 新增前准备实际尺寸，以最新Store计算无重叠位置，既有节点保持原位，坐标随本次新增一起严格保存。
2. 一组节点的关系建立后，按明确范围复用原生局部排版。已有模板优先保留相对位置并整体放到空白区域；生成后的整理只在确有尺寸变化/新增结果节点、且本轮节点未被用户移动时按需进行。

不把“每次生成后全图排版”作为默认补救：节点创建到结果完成之前已经会遮挡；全图排版会改用户布局；原生算法也不保证组与组之间无重叠。

## 2. 当前坐标来自哪里

| 入口 | 坐标来源 | 是否保证无重叠 |
| --- | --- | --- |
| Agent普通节点 | 工具显式position；缺省为{x:0,y:0} | 否，多个缺省节点在原点重叠 |
| Agent图片素材 | 工具显式position；缺省为{x:0,y:0} | 否，同上 |
| 原生createNode | 直接写basic.position | 没有空间计算 |
| 原生addNode | 准备尺寸、命名、选择状态、保存 | 没有自动避让 |
| UI菜单/普通新增 | 鼠标菜单或视口中心转换为画布坐标；中心有随机偏移 | 随机散开不保证无重叠，且依赖ReactFlow视图 |
| 媒体粘贴/拖入 | 鼠标位置；多文件按40px级联偏移 | 不保证无重叠 |
| 前后接工具节点 | 相对原节点固定偏移，加随机量 | 不检查其他节点，也不按所有实际尺寸避让 |
| 工具输出子节点 | 工具右侧；单节点随机偏移，多结果纵排默认480px间距 | 可能撞到其他节点，长图可能超过间距 |
| 模板导入 | 保留内部结构，将根节点整体移到旧节点右侧maxX+200 | 思路可复用，但旧范围helper对组和尺寸的计算不够完整 |

直接根因是[createAgentNode](../../../../../desktop-canvas-plugin/canvas-app/src/agent-node-policy.ts:98)和[createAgentAssetNode](../../../../../desktop-canvas-plugin/canvas-app/src/agent-node-policy.ts:111)的缺省原点，以及[addNode](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/store/flowStoreCore.ts:691)没有避让步骤。

普通UI的[视口坐标](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/components/canvasFlow/utils/toolUtil.ts:318)、[工具后续节点](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/components/canvasFlow/hooks.ts:783)、[结果子节点](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/components/canvasFlow/hooks.ts:898)和[模板整体移动](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/store/flowStoreCore.ts:649)并非同一个放置策略。

历史任务4实账还观察到Agent主动传position:{x:0,y:0}。因此只替换“字段缺省时”的默认值不够覆盖所有调用行为；工具契约与说明也必须明确默认自动放置。当前NodeDetail不含完整position/size/parentId，不能要求Agent仅靠节点读取自行推算空白空间。

## 3. 原生一键排版能复用什么

[autoLayout.layoutSelectedNodes](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/components/canvasFlow/utils/autoLayout.ts:274)是纯函数，无需打开画布或取得ReactFlow视图实例：

```text
输入：选中节点、完整边、完整节点、mode
mode：grid / horizontal / vertical
输出：节点position更新、必要的组style尺寸更新
```

- grid按节点数量确定行列，采用列最大宽/行最大高；间距X=120、Y=80。
- horizontal/vertical复用已有Dagre，依据选区内部的边做LR/TB有向排版；不等同于grid的间距策略。
- 顶层选区保持原选区左上角锚点。
- 组内使用相对坐标、50px留白并更新组容器尺寸。

必须处理的边界：

1. **它不检查未选节点。** 新节点彼此排开后，仍可能撞到旧节点。需要对整理结果再做整体放置/障碍检查。
2. **选区会扩大。** 选中一个组内孩子，会扩展到同组全部孩子；选中组会展开孩子。局部自动排版不能静默移动未授权的旧节点。
3. **各组分开排内部，组容器原点不移动。** 对全图传所有节点也不能保证组间无重叠；组扩张可能影响旁边内容。
4. **当前Store入口不是严格Agent写入。** [flowStoreCore.layoutSelectedNodes](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/store/flowStoreCore.ts:991)返回void、先set再发partialUpdate，不等待保存，也没有Agent的expectedVersion/guard/strictReceipt。可复用纯算法，但Agent调用要补受保护的保存路径。

例如：两枚新节点内部grid排成(0,0)、(520,0)时，若旧节点正位于(520,0)，本次内部排版仍会发生新旧遮挡。这是根据源码间距的示意，不是本轮业务运行结果。

## 4. 放置函数应该做什么

建议以Client无界面服务作为执行位置，使用完整原生Store，避免把全部节点坐标发给模型计算。下列函数名/签名是后续设计建议，尚不存在：

```ts
resolveNewNodePlacement({
  existingNodes,
  newNodes,
  newEdges,
  mode,              // single / grid / horizontal / preserve
  anchorNodeIds?,
}): PositionUpdates
```

单节点与一批节点共用同一几何基础；不额外建立坐标队列，沿用当前guard和保存队列。

### 单节点：首期采用确定性的安全追加

空画布以原点为初始锚点；非空画布计算既有内容的真实外边界，将新节点放到右侧留有间距的空白位置。所有旧节点保持原位。

这先解决现有遮挡问题。后续连线接入后，可以把“靠近指定上游节点”作为放置偏好，再检查冲突；最终空位仍由插件计算。

### 一批节点：内部排版，再整体放置

- 关联流程：复用原生horizontal有向排版，取得新流程内部相对位置。
- 并列素材：复用grid。
- 导入已有模板：保留其内部布局。

随后计算这批内容外包矩形，将整批移到与旧内容不冲突的区域；只平移顶层节点，组内孩子保留相对父组的坐标。批次内节点之间、批次与旧节点之间都必须检查。

若新增与连线已经是同一次业务提交，坐标与节点/边一起保存，不先保存重叠数据再无条件追加一次排版保存。现有后端不是任意跨请求事务；分步调用的部分成功需要分别报告。

### 纯计算必须使用可信几何

- 媒体使用prepareNodesForCreate之后的可信measured/width/height；组读取style.width/height，其他类型采用可靠显式尺寸或原生默认值。
- 原生媒体默认按最短边400计算显示尺寸，[尺寸公式](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/components/canvasFlow/utils/mediaDimensions.ts:141)。21:9可能约933×400，9:21可能约400×933；固定450/480间距不够。
- 图片像素分辨率不是画布显示尺寸；不能把2048×2048直接当作画布占用，也不能把上传节点aspect_ratio当作源图属性。
- 子节点position为父组局部坐标；障碍计算需转换为绝对坐标。父组包含其孩子属于正常包含关系，不视为遮挡；顶层新增则应避让组外框及超出组外的内容。
- 现有[toolUtil.getMaxX](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/components/canvasFlow/utils/toolUtil.ts:275)不处理父组坐标、组style尺寸；现有getNodesRange与排版尺寸来源也不一致，不能直接充当可靠碰撞函数。
- 尺寸未知时保留估算状态，采用保守占位。不要把估算值持久化成“真实measured”。尺寸加载失败不能承诺所有未来显示尺寸均无冲突。

首轮当前工具只新增顶层节点，可以先完成顶层自动放置并将既有组当障碍；组内自动插入/扩张在组能力接入时单独处理，避免顺带改变原生组编辑。

## 5. 调用时机、坐标契约与保护

### 最终放置在尺寸准备后完成

[当前addNode](../../../../../desktop-canvas-plugin/canvas-app/legacy/src/store/flowStoreCore.ts:691)已经在Agent guard内执行；700行等待媒体尺寸，701行重新读取Store。推荐顺序：

```text
构造原生节点 → 准备尺寸 → 复核上下文/版本
  → 读取最新完整Store → 计算位置 → set并严格保存 → saved回执
```

最新几何读取、计算与set之间不插入异步等待。每次新调用按真实当前版本校验；冲突仍明确返回，不为自动修位置绕过版本检查或自动重放旧请求。既有未知结果和回滚规则继续复用。

### 显式坐标不能被当成自动标记

{x:0,y:0}是合法精确位置，不能以“坐标等于0”猜测用户是否要求自动放置。

推荐下一版模型工具明确区分auto与absolute放置，默认auto；Agent一般只表达依赖/邻近偏好，插件决定像素坐标。精确坐标只有明确选择absolute时才使用。已有position调用必须制定并测试兼容规则，不能静默改变旧字段含义；原生UI/内部显式坐标路径保持原行为。

最低修复是缺省自动放置加工具说明默认省略position，但历史模型主动0,0仍是风险，因此完整验收应覆盖新版工具默认auto以及精确坐标两条路径。具体兼容解析在实施计划中落实。

### 局部排版应有独立严格回执

后续可开放 `canvas_layout({canvasId,expectedVersion,nodeIds,mode})`，内部使用原生算法及同一保存队列；入参不让Agent提供完整raw节点覆盖。

- 默认仅处理指定的本轮节点；用户明确要求全图整理才扩大范围。
- 先计算实际更新ID，检查组扩展是否触及未授权旧内容；无法满足局部范围则拒绝或报告需扩大范围，不能偷偷移动。
- 沿用版本、编辑/拖动保护，报告实际移动节点、必要组尺寸更新和保存版本。
- 新增已saved而后续排版失败，新增仍成功；单独报告排版状态，不能重新创建节点。
- 排版保存unknown时停止重复移动，先核对现状。

## 6. 什么时候自动调用排版

| 情况 | 推荐行为 |
| --- | --- |
| 新增一个节点 | 新增时算空位，坐标随新增保存；无需排全图 |
| 新增一组有关联的节点 | 首次保存前做内部有向排版及整体避让 |
| 一次完整流程分多步创建、连线 | 关系形成后可整理明确的本轮新增集合；既有上游作固定锚点 |
| 工具完成并新增结果子节点 | 子节点进入同一个放置入口；按实际尺寸靠工具附近避让 |
| 生成只回写已有节点、几何没变化 | 保持布局 |
| 尺寸变化导致本轮新增内容冲突 | 尺寸就绪后按需做一次受保护局部校准；用户已移动的节点保持原位 |
| 期间用户拖动/编辑 | 跳过自动整理或返回忙/冲突；保留用户操作 |
| 用户明确要求“整理整个画布” | 显式布局操作，检查组实际范围与跨组碰撞，不把现有局部算法当作通用全图保证 |

“本轮新增集合”通过业务步骤已有节点ID/回执明确，不依赖当前UI选中状态。完成后校准是补充能力，不替代新增时的防遮挡，也不在每次状态事件触发排版。

## 7. 建议实施位置与验收

规划位置，具体文件拆分以专项实施计划为准：

- `canvas-app/src/agent-node-policy.ts`：移除自动路径的固定原点决策，保留原生节点工厂与显式路径。
- 新增薄放置/绝对矩形计算模块，复用原生默认尺寸、媒体尺寸与autoLayout。
- `canvas-app/legacy/src/store/flowStoreCore.ts`：在Agent options路径、尺寸准备之后完成放置；UI调用默认行为保持。局部layout增加严格options路径。
- shared协议、Host工具与Client适配：明确放置策略；按后续能力阶段开放局部layout；读取增加位置/尺寸/父组，供用户核对，不要求模型自己算。
- 后续工具结果服务/模板导入适配复用同一放置规则，避免继续独立固定偏移。

完成标准：

1. 关闭画布连续新增文本、普通媒体、图片素材，节点不重叠；后端重载坐标与原生显示一致。
2. 宽图、长图、异步尺寸准备、负坐标旧内容、组外边界均被正确计入占用。
3. 同批多节点内部及与旧节点之间无冲突；旧位置不变。
4. 组坐标转换正确；父子包含不误报；局部整理不移动未授权旧节点或同组孩子。
5. 工具默认auto不再主动固定0,0；明确absolute坐标按契约保留，不静默漂移。
6. 同版本并发调用保持原冲突保护，不重复计算后强写；拒绝/unknown仍遵守原语义。
7. 用户拖拽/编辑期间不自动移动其节点；生成后的局部校准不覆盖用户重新摆放。
8. 排版保存失败独立报告，不重复新增，不改正文、参数或素材；原生手动新增与排版行为保持。

本轮没有执行上述新增回归，这些是待实现后的标准。建议将单节点自动防重叠排在通用节点/连线/执行扩展之前；批次排版和工具结果避让随相应能力一起接入。
