# 因赛AI 1.0.0-rc.14 Windows upgrade validation

Windows-only validation artifact; not approved for OSS pointer promotion.

- The installer extracts its newly built compatibility uninstaller to its
  temporary directory after checking the registered uninstall path and product
  executable. It does not overwrite the old uninstaller in the installation.
- Atomic relocation and restore use extended-length source and staging paths.
  File I/O paths are separate from registry/display paths, including UNC handling.
- Keeps rc13 append-only diagnostic logging and stops on failure without regular
  non-atomic uninstall fallback. Failure to launch the compatibility executable
  does not fall back to the old executable.
- Core Runtime and business features remain on the rc12 baseline.

Validation gates: Windows NSIS function fixtures; complete isolated test-product
upgrade with a 260-character file; actual rc7 → rc14 manual upgrade on the affected
machine; then client-triggered automatic upgrade. Do not treat the fixture as
acceptance of the real product, installed user data, or all-users scope.

Use release.yml workflow_dispatch with candidate_tag=v1.0.0-rc.14 and
target=windows-x64. No release tag or update-pointer change for this build.
