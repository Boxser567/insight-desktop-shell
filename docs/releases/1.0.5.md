# 因赛AI v1.0.5 Candidate

本版本沿用 1.0.4 已验证的新 Core、提示词增强和桌面集成，验证三平台 Candidate 升级与
完整安装器恢复链路。正式 App ID/userData 不变；Candidate 由签名投放指针控制，安装器
仍使用 v2 的统一正式包身份，默认后台检查只读取 Stable。

## 固定范围

- Core Runtime 保持 `insight-runtime-v0.2.1-alpha.1-insight.1`，提交 `25a49c53c4e0c003a8469ee243aa5d1365df80cd`。
- 三个 Runtime 归档 URL/SHA-256、整体数据 Schema、Profile/账号 Schema 和提示词增强 `0.2.7` 均不变。
- Shell 版本为 `1.0.5`，发布日期为 2026-10-09；沿用 `optional` 更新策略。
- 恢复目标为新 Stable `1.0.4`，读整体 Data Schema 1..2，能够读取 Candidate 写入的 Schema 2。
- 不把 Candidate 转为 Stable。本轮仅投放三个 `candidate-v2/<target>/current.json`；Stable 保持 1.0.4。

## 发布接受依据

2026-10-09 操作者明确授权：采用已有 Dev 模式多轮本地实测、三平台实际包启动与
历史 v3→v4→恢复续写→重启读取证明、签名/公证与完整 CDN 校验，不追加重复人工实测。
[1.0.4 恢复基线记录](1.0.4-recovery-acceptance.md) 保留证据来源与未新增实测的范围；
该决定不表示新增三平台人工覆盖安装、真实模型或 Memory Evolve 业务测试已经完成。

## 发布门禁与状态

先接受三个 1.0.4 恢复基线目标并推广 Stable，确认公网签名链；再从固定 `v1.0.5` tag
构建三平台安装器，执行原生包内启动、数据恢复、签名、公证与容器校验。所有自动门禁通过后，
使用 `publish-candidate-all` 投放三个 Candidate 目标，保留服务端及客户端的恢复兼容检查。
任一构建平台失败，取消整轮、修复后重试；不移动 tag 或覆盖不可变资产。
