# 达人推荐报告模板

## 1. 结论先行

- 目标与此次达人组合的核心策略。
- 优先邀约、测试、条件型补充和淘汰名单。
- 需要立即确认的排他或预算风险。

## 2. 产品—场景—达人类型映射

|产品能力/痛点|内容场景|适合达人类型|关键验证指标|
|---|---|---|---|

## 3. 候选横向比较

先给平台能力表：候选发现、账号、作品、评论、受众和报价分别标注 `live/fallback/catalog/failed/seed_only/unavailable`。

候选按平台和内容形态分组比较：

|平台|达人/creator_key|粉丝数（抓取时点）|有效作品数|平台内可比表现|商业能力强项|商业证据覆盖率|本品/品类证据|报价状态|结论|
|---|---|---:|---:|---|---|---:|---|---|---|

跨平台不提供单一总分榜；用角色、场景、人群证据、内容形式和平台增量覆盖形成组合。

## 4. 逐人尽调卡

每位达人使用同一结构：

1. 平台、`creator_key`、可选 `entity_cluster_id`、粉丝数与抓取时点，以及与实际有效作品样本的规模/内容效率解读；
2. 结论与推荐层级；
3. 最多近 10 条有效作品、实际样本数、内容形态、内容年龄，以及接口确实返回的播放/阅读、完播率、互动与构成；
4. 本品、竞品及品类合作证据；
5. 直接数据支持的受众匹配；无接口/授权数据时写 `unavailable`；
6. 达人商业能力画像：传播力、人群匹配、种草、转化、性价比五个分项，稳定与风险单列；展示原始证据、证据性质与 `commercial_evidence_coverage`；
7. 推荐投放角色及依据，明确更适合声量、专业验证、场景种草、搜索内容、转化测试或素材资产中的哪一项；
8. 内容命题与建议交付；
9. 风险与签约前待核事项；
10. 各能力路由状态、`evidence_coverage`、事实边界与数据抓取日期。

商业能力模块使用以下结构，不得只给一个总分：

|能力维度|分数/状态|直接证据|证据性质|业务解释|
|---|---:|---|---|---|
|内容传播力| | |`observed_public` 等|适合承担的触达任务|
|人群匹配度| | | |目标人群匹配或缺口|
|种草能力| | | |兴趣、搜索或产品理解信号|
|带货转化力| | | |GMV/点击/转化区间或待核验|
|商业性价比| | | |报价与预估效率的同 cohort 判断|
|稳定与风险|低/中/高/未知| | |预算限制或签约门槛|

表后分别显示 `recommendation_fit_score`、`commercial_capability_score`、`risk_adjusted_score` 和 `commercial_evidence_coverage`。无法满足评分条件时总分填 `null`，但仍保留可验证分项、推荐角色及待补数据。

## 5. 投放组合与预算规划（`portfolio` / `full_plan` 必填）

### 5.1 组合角色

|达人|主角色|商业能力依据|目标人群/场景|内容任务|选择理由|替补|签约门槛|
|---|---|---|---|---|---|---|---|

### 5.2 覆盖与重叠

按角色、人群、场景和内容形式说明 `covered`、`gap` 或 `overlap`。重叠项必须解释为何保留；不得把单达人评分前 N 名直接视为最优组合。

### 5.3 预算闭合

|预算科目|金额|状态（已报价/估算/预留/未知）|说明|
|---|---:|---|---|

列出总预算、已分配金额、未解决成本和 `closed / partial / not_plannable` 状态。达人费以外至少检查平台/税费、制作与授权、加热测试、承接与归因、机动预留；未知费用不得默认成零。

### 5.4 分阶段测试

|阶段|达人/内容|观察窗口|进入条件|成功/加投规则|停止/修正规则|指标来源|
|---|---|---|---|---|---|---|

没有品牌目标或真实基线时使用相对规则，不自行生成固定搜索增长、CPA、成交或 ROI 阈值。

## 6. 执行与核验

- `shortlist` 模式的分层名单，或 `portfolio` / `full_plan` 模式的组合与预算结论；
- 测试脚本及有依据的加投/停止规则；
- 排他、素材授权、白名单、评论置顶、搜索词、跳转链路及归因回传清单；
- 数据未覆盖的字段及补数方式。

## 7. 投中监测交接包（`portfolio` / `full_plan` 必填）

附结构化 `monitoring_handoff`，包括计划 ID/版本、达人监测注册表、发布窗口与应发数量、角色/场景/信息点、预算、KPI 公式与阈值、逐指标基线、一方数据映射和上游查询/风险/证据引用。投前未知的内容 URL 保持空值，不得删除对应的发现任务。
